# Tiny settlement and first useful robot

The owner approved continued development of the playable concept and permits open-source assets. The reference design's M2 goal is to use expedition salvage at home and watch a robot perform useful non-terrain work. This session implements that small loop. Existing M1 combat/extraction and unfinished M0 benchmarking remain intact.

The player opens the home builder with B. Keys1/2/3 select storage/workshop/charger; the mouse previews a snapped200cm cell, left mouse places a valid structure, right mouse cancels selection, and B closes the builder. Building is permitted while the player is inside the protected home radius. Placement is limited to the home clearing: grid center(-1500,-550,10), X cells[-4,4], Y[-3,3]. Occupied cells and world collision reject placement without spending. Each structure has one instance. Storage costs4 salvage and adds8 carrying slots; workshop costs6; charger costs4. After all three, key4 in the builder constructs one hauler for8 salvage. Defaults are data-driven tuning values.

J enables/disables hauling. The bot collects loose salvage only when no living hostile is within650cm, so clearing the ruin remains valuable. Its cargo capacity is4. It travels via Recast/AIController, claims a pickup before committing cargo, and banks at the built storage. The bot returns to the charger when battery reserve is low, recharges, and resumes work. A disabled job still returns cargo and recharges. Unreachable pickups are skipped temporarily; navigation failures and low battery are visible states. One bot and a small finite field keep this slice manageable.

Authoritative structures, cargo, battery and hauling intent extend pure data, while a new DownstreamColony module owns placement preview and robot/building presentation/navigation. DownstreamCombat issues builder requests and marks living hostiles; Render reads colony/state for HUD. Colony depends only Downstream/Sim, avoiding a Combat cycle.

Save schema2 preserves bank, starter skill, placed structure cells, bot ownership, cargo, battery and hauling preference. Schema1 migrates safely to an empty settlement without losing bank/skill. Invalid structures/robot state block writes and preserve the file. Build/cargo/banking changes commit memory only after successful writes; battery checkpoints every5seconds and on normal shutdown. Field enemies/pickups still reset each launch; saved bot cargo returns home on reload. This is explicit slice persistence, not seed-and-delta world persistence.

Use existing original3D props for readable building/robot prototypes. Add small CC0 feedback assets if useful, retain license/source hashes, and document actual imports. No paid acquisition, full skill tree, combat robot, water, arbitrary building rotation/demolition, worker simulation or offline catch-up is added.

Acceptance: pure spending/placement/robot invariants pass after observed RED; native targets and prior suites remain green; isolated Unreal verification builds all structures, rejects invalid/overlapping/duplicate/unaffordable placement without spending, constructs a hauler, observes a real pickup/delivery and recharge, tests hostile avoidance, and reloads schema2 plus a legacy schema1 fixture. Review a visible standalone frame and commit/push source, assets, docs and durable evidence.
