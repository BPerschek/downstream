# Initial decisions — 2026-10-09

1. **Start with M0.** Prove camera, project setup, art transfer and deterministic native data before M1 combat/extraction. Do not let terrain/water become the entire game.
2. **Keep the runnable project available.** Blueprint movement and camera work without a native toolchain. Native source is staged outside the project because uncompiled Source targets also trigger Unreal's missing-target launch dialog. Activation checks tools, copies source, builds Editor and Game, and retains the descriptor only after success. An unsuccessful first build restores the Blueprint descriptor and removes its newly created source copy. A Game-only build also restores the original descriptor.
3. **Simulation owns plain data.** DownstreamSim has no rendering or Actor dependencies. Its Unreal wrapper depends Core only. Downstream now owns the compiled game-thread adapter and queued commands.
4. **Fixed time is separate from frames.** Default time step is 0.1 seconds. With no recurring simulation yet, empty ticks can aggregate. Future water/jobs require a bounded per-tick policy and snapshots before worker ownership; the current class is deliberately single-owner.
5. **Original art is editable.** Blender metres export to Unreal centimetres; every export includes a measured manifest. Nine meshes total 3,424 triangles. The shelter's automatic convex collision currently treats it as an exterior obstacle; interior traversal needs wall/door collision sections.
6. **Add boundaries when needed.** DownstreamRender now owns chunk presentation/HUD; DownstreamCombat owns GAS health/native attacks and enemy AI. Combat depends Downstream, Render depends Combat; Combat must not depend Render. Future World/Bots/Colony/Settlements remain deferred. Seeded terrain is not a complete world generator.
7. **Actor versus Mass remains undecided.** No equivalent-motion benchmark has run. The owner-installed AdaptivePathfindingSystem plugin is enabled locally, but current gameplay uses regular Recast/AIController navigation; plugin algorithms are not integrated.
8. **Keep performance claims measured.** Native targets/automation are now available. No packaged GPU benchmark has established1080p60FPS. Full M0 acceptance remains open.
9. **Navigation is built before delivery and at prototype startup.** A Python commandlet creates geometry but does not run the full editor navigation-registration lifecycle. Regeneration therefore runs a separate hidden editor, builds navigation and saves the map. The initial Dynamic navmesh also requires a runtime build in this environment; play.ps1 explicitly supplies RebuildNavigation as its startup console command. The verifier records and executes that same startup command. This temporary full rebuild is for the small static M0 map; it does not establish the future requirement for local navigation invalidation after terrain edits.
10. **Clear stale native target metadata when returning to Blueprint.** Unreal retains Intermediate/TargetInfo.json and compiled rules after native Source is removed. Those cached targets can still request a missing receipt at standalone startup. The initial stale caches were moved into ignored build/ backups; failed first native activation also clears TargetInfo.json after source cleanup.
11. **Prioritize a working gameplay concept.** The owner's subsequent request authorizes a small M1 expedition before M0 profiling/Mass completion. M1 is a separate saved level; M0 remains a technical reference. Original meshes/audio avoid missing pack dependencies.
12. **Persist only committed home progress.** Pure ExpeditionState owns inventory/stash/one starter node. Versioned JSON stores bank and skill after successful disk commit; carry and field reset on launch. Tests use an isolated save directory. Full world/entity persistence and XP are deferred.
13. **Use GAS for health with a narrow prototype bridge.** Native attribute sets/ASC own health; attacks and cooldowns remain native frame-rate gameplay. Full granted ability/effect definitions are future work. [Epic's GAS component/attributes guide](https://dev.epicgames.com/documentation/unreal-engine/gameplay-ability-system-component-and-gameplay-attributes-in-unreal-engine) provides the extension seam.
